# Contributing to gx

## Prerequisites

- [Rust](https://www.rust-lang.org/tools/install) and Cargo (declared MSRV: 1.75;
  CI uses stable Rust)
- Git
- Bash, zsh and fish for the Unix shell integration tests

## Setup and development

```sh
git clone https://github.com/joshuaboys/gx
cd gx
cargo build
cargo run -p gx -- --help
```

Build the standalone binary with `cargo build --release`. It is written to
`target/release/gx` (`gx.exe` on Windows).

## Validation

Run the same Rust checks used by CI before opening a PR:

```sh
cargo fmt --check
cargo clippy --all-targets --workspace -- -D warnings
cargo test --workspace
```

Use `cargo fmt` to apply formatting. CI runs on Linux, macOS and Windows.
On Unix, install zsh and fish (`sudo apt-get install zsh fish` on Ubuntu;
`brew install bash fish` on macOS, where zsh is included). Local shell tests skip
unavailable shells with a diagnostic; CI requires all three. Windows runs the
portable Rust tests, PowerShell output snapshots and a native PowerShell help
test, but not the Unix shell execution tests.

The APS launcher regression needs Bash 4 or newer. On macOS, select Homebrew
Bash for that test while keeping the other shell tests on the system shell:

```sh
GX_TEST_APS_BASH="$(brew --prefix bash)/bin/bash" cargo test --workspace
```

Integration tests use temporary home directories and local Git repositories.
The installer test substitutes local downloads and needs no network access.
Tests under `crates/gx/tests/snapshots.rs` compare output byte-for-byte with
committed goldens. When intentionally changing CLI or shell output, update only
the affected snapshots and review every diff:

```sh
INSTA_UPDATE=always cargo test --test snapshots snapshot_shell_init
```

In PowerShell, set `$env:INSTA_UPDATE = 'always'` before the test command and
remove it afterwards with `Remove-Item Env:INSTA_UPDATE`.

There is no general Markdown validation gate. Check documentation examples
against the CLI and verify local links and heading anchors when editing docs.

## Project structure and conventions

See [AGENTS.md](AGENTS.md) for the source layout and full repository guidelines.

- Rust 2021; prefer the standard library and existing dependencies.
- Use Git subprocesses; keep the implementation synchronous.
- Shell integration is generated by `gx shell-init`.
- Use Conventional Commits (`feat:`, `fix:`, `docs:`, etc.).
- PRs should explain the user-visible change, include validation evidence and
  update documentation for CLI changes.
